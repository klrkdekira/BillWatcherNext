# Data model notes

The authoritative schema is the Alembic migrations and the SQLAlchemy mappings. This file records
the conventions that are not visible in a column definition.

## Event fingerprints

Bill event fingerprints are SHA-256 over the stable serialization of bill ID, chamber, event type,
start/end dates, sequence, normalized source label, and normalized source value. Run, snapshot,
and observation timestamps are deliberately excluded so replay is idempotent.

## Search unit ownership

Search units are owned by the application and rebuilt in the same transaction as the write that
caused them; no database trigger maintains them (ADR-006).

A unit is either a **bill metadata unit** or a **document text unit**:

| Unit kind | `content_a` (weight A) | `content` (weight B or C) | Rows |
| --- | --- | --- | --- |
| `bill_metadata` | raw and normalized identifiers | titles, year, chamber, status, presenter (weight B) | one per bill |
| `document_text` | empty | one page of one document version's current extraction (weight C) | one per page, split further by `part` above 200,000 characters |

The `tsv` column is generated by PostgreSQL from those two fields plus `unit_kind`, so the weights
cannot drift from the data. Superseded document versions keep their units with `is_current` false;
they are searchable only with `include_superseded=1`. See ADR-007 for ranking and pagination.

## Chunks and embeddings

Chunks hang off a `document_extraction`, which hangs off an immutable `document_version`. A
citation therefore always resolves to specific bytes retrieved on a specific date. `document_chunks`
records the `chunker_version` that produced it; a chunker bump writes a new set and demotes the
old one rather than editing it.

`chunk_embeddings` holds one vector per chunk per model, so two models coexist during a
migration. The stored vector width is `EMBEDDING_DIMENSION` in `billwatcher.models` (ADR-008); a
model with a different width requires its own migration.

## Document relations

`document_relations` records links between distinct documents. Documents are never auto-merged.
The only heuristic currently written is the unambiguous HANDOFF 9.2 case — identical stored bytes
served at a second canonical URL — which proposes `reissue_of` with `decided_by = heuristic` and
raises a `document_relation_proposed` anomaly for a person to confirm. Broader revision
heuristics wait on assumption A11.

## Retention classes

See ADR-010. In short: transport logs are aggregated then deleted, old extractions are pruned to
the current version plus one, and document versions, their blobs, record changes, bill events, and
presence observations are never pruned by any job.
